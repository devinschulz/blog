# Devin Schulz

Personal portfolio built with Hugo, Tailwind CSS v4, TypeScript, and Hotwire.

## Development

```sh
npm ci
npm run serve -- --destination /private/tmp/devin-blog-preview
```

Hugo serves the site at http://localhost:1313 and rebuilds templates, styles, and scripts as files change. A separate preview destination prevents the development server from overwriting the production files used by browser tests.

## Build and verify

```sh
npm run check
npm run check:a11y
```

`check` runs TypeScript, builds the site, and verifies metadata, links, assets, RSS, sitemap, and redirect mappings. `check:a11y` audits every page for accessibility and text reflow in desktop and narrow viewports, in light and dark themes. It also checks the project gallery, theme persistence, keyboard navigation, archived GIF controls, and navigation without JavaScript.

Deploy `dist/`, produced by `npm run build`. Production builds clean retired generated files from this directory so old script bundles are not carried into the deployment. Hugo compiles Tailwind and bundles TypeScript through `js.Build`, then fingerprints production assets. No separate frontend framework or bundler is needed.

## Design and interactions

The homepage follows a narrow single-column reading layout, informed by mellow.dev, jonnybelton.co, and the restrained typography of bleibtgleich.dev. The 720px outer shell has a 656px desktop reading track shared by navigation, content, and footer. “Hi, I’m Devin.” uses 24px medium DM Sans, followed by the existing author introduction and a plain About link. The quieter shared header contains Writing, Work, Search, and the theme control. Eight recent articles use 24–28px titles (28–32px for the lead), 16px descriptions, muted dates, and one title link per entry. Whitespace separates entries without borders or a sidebar. RSS, Topics, and older writing remain available through the footer and full archive. Page-colored headers and blue keyboard focus are preserved; titles are native HTML text.

The opening headline is “Making complex software feel simple.” It introduces the product interfaces I build and links directly to selected work and the InVision measurement example. The About section describes my approach to design and engineering, with a link to recent writing. Project descriptions name the actual interfaces and contributions, and the contact footer uses a neutral invitation to compare notes.

Selected Work begins with Stripe, listing Checkout Studio followed by Console as the current team. The shared facts live in `data/experience.yaml` and appear in both the homepage and its Markdown export. This entry describes the confirmed role and team sequence; the three illustrated case studies follow it.

Supporting labels and project metadata use a 12px minimum. Navigation arrows share `layouts/partials/arrow-icon.html`; compact controls share 44px targets, 16px horizontal padding, and 8px icon gaps. Menu and theme controls keep transparent backgrounds. Keyboard focus uses the semantic blue accent, including mobile navigation and the search field. Fixed dark code surfaces use Pale Electric Blue, fixed white project and skip controls use Electric Blue, and forced colors retain system Highlight. On narrow screens the hero's bottom links stack so the larger labels fit comfortably.

The InVision case study includes a small SVG measurement example built with a Stimulus controller. Visitors can compare separated, overlapping, and contained layers, then change display zoom without changing the design-pixel measurements. The blue layer can be dragged, moved one pixel with arrow keys (ten with Shift), or nudged with tap controls. Distances and relationship explanations follow its position; Reset restores the starting layer, and Escape cancels a drag. Only the layer captures touch gestures, leaving the rest of the page scrollable. Geometry is independent of rendering in `assets/js/measurements.ts`. Native select and range controls support touch and keyboard input; without JavaScript, the annotated 60px example and its explanation remain visible. Browser tests cover movement, bounds, zoom invariance, accessibility, and fallback in Chromium and iPhone WebKit. The example illustrates the documented approach rather than reproducing the original Inspect engine.

Inspect mode is a hidden look at the actual page layout. Type `inspect` outside an editable field, or tap the logo five times, to reveal it. Move, tap, or focus a page control to inspect its size, padding, margin, typography, and text color; Parent selects its container. Escape or Done closes the panel. A normal single logo click still goes home, and scrolling and browser zoom remain available. Navigation closes Inspect before a Turbo snapshot is saved. It creates no overlay, observers, or render loop until activated, and removes them on exit. The keyboard-triggered interface updates instantly without animation.

Logo clicks also launch a small bouncing `+1`, `+2`, and so on, styled as monospace superscripts above the logo's period. Each click gets its own count. The tally lasts through Turbo navigation and resets on a full reload. Opening Inspect clears the feedback and pauses counting; after exiting, the next click starts at `+1`. Clicking the logo while already home returns to the top without replacing the page. Keyboard navigation keeps its regular link behavior; reduced motion shows one static count without the bounce. Feedback is removed before navigation snapshots are saved.

Titles throughout the homepage, archives, articles, topics, work overview, and case studies are native, selectable HTML text. There are no graphics canvases, shaders, water or fish effects, or graphics-engine dependencies. Typography responds directly to the theme and remains readable without JavaScript. Browser checks cover a 200% desktop zoom viewport and doubled text.

Project previews use `assets/js/controllers/project_preview_controller.ts`, a small Stimulus controller. Show other view switches between two real screenshots after they decode, preserves keyboard focus, and announces the selected view. A failed decode leaves the current image visible and permits retry. Navigation resets the preview and ignores late decode results. Without JavaScript, the first screenshot and case-study link remain usable.

`layouts/partials/work.html` contains the project data. Layout, typography, and responsive states use Tailwind utilities directly in the Hugo templates and TypeScript. `assets/css/site.css` contains Tailwind imports, semantic theme tokens, shared utilities, and global accessibility defaults. Fonts are self-hosted in `static/fonts/`. The favicon uses a white lowercase “d.” on ultramarine; `npm run build:icons` regenerates its 16/32/48px ICO, 16/32px PNG fallbacks, 180px Apple touch icon, and Safari pinned-tab mask from `static/favicon.svg`. Icon links use content-hashed filenames so new versions receive new URLs.

The writing archive shares the homepage’s open neutral headers and native typography, followed by open editorial rows. Original article dates and topics remain visible, with an RSS link above the list.

Writing in the shared navigation opens the full archive directly and marks the current section. The archive groups posts by year with native year shortcuts and compact dated rows. Article and archive headers use a smaller type scale and tighter spacing to bring reading choices and prose into the opening viewport. Article prose is capped at 68ch or 38rem, while code and figures keep the wider reading track. Contents links use native fragment navigation and highlight the current section; expanded menu and contents controls show a minus. Code captions indicate horizontal scrolling only when the block overflows. More writing ranks shared topics first, with publication recency breaking ties.

Technical examples have a Copy control when the Clipboard API is available. It copies the code with its original whitespace, confirms with a static check and “Copied” label, and announces success to assistive technology. Clipboard denial leaves a manual-copy instruction and a retry action. Without JavaScript or clipboard support, code remains selectable and keyboard-scrollable. Copy controls and code regions use an inset pale blue focus outline in both themes. The Stimulus controller clears temporary feedback and pending clipboard results before Turbo history snapshots and on navigation.

Articles with contents and a reading time of at least five minutes remember the last section reached beyond the first section. Returning readers get a quiet “Continue reading” link above the article body; following it moves both the reading position and keyboard focus to the section. Direct fragment links take precedence, and reaching the end clears the place. Only the section identifier is stored in the visitor’s browser, scoped to the article URL, when leaving the article or hiding the tab. Blocked storage and missing sections leave normal reading intact.

Article pages use an open page-colored title header with the original date, topics, and reading time. Titles wrap naturally and remain selectable at every viewport and text size. The reading column includes keyboard-scrollable code blocks, semantic typography, and native section links. Longer posts have a sticky contents list on desktop and a collapsible contents list on mobile. Archive context remains visible on historical posts, and related writing closes each article. Article bodies, original code, and Markdown exports are unchanged by the layout.

Case studies share an open neutral project-name header and original outcome headline. The product screenshot follows the title and description with space above it, rather than overlapping a panel. Project summaries and role details sit below the image. The header uses the same native typography as the homepage.

The theme follows the system until a visitor chooses light or dark; that choice is stored locally. An inline script resolves the theme before styles load, with system defaults when storage is unavailable. Inline HTML and body colors prevent a light background during loading, and CSS follows the system without JavaScript. Safari's toolbar color follows the page and chosen theme. Theme regressions run in Chromium and iPhone WebKit; install both with `npx playwright install chromium webkit` before running the browser checks. Turbo and supported full-page navigations use native view transitions: the old page stays opaque while the new page fades over it in 160ms. Reduced motion uses an immediate swap, and browsers without view transitions retain normal navigation. The native mobile menu supports Escape and section focus. Existing case-study and article URLs are preserved. The shared JavaScript registers the site’s Stimulus controllers; article demos remain separate.

## Content

Use one or two topic tags per article, based on what the reader will learn. The current topics are JavaScript (language and browser APIs), React (components and state), CSS (styling), Design (interface behavior), Tooling (development and debugging tools), APIs (data services), Websites (building and running a personal site), and Career (collaboration and working life). Prefer these topics over individual libraries, incidental technologies, or formats such as “Opinion” and “Today I Learned.” Add a topic when it offers a useful, distinct collection of articles. When retiring a tag, preserve its URL in `static/_redirects` and regenerate share cards after changing tags.

The article on chat scroll position embeds an isolated React demo. React is bundled only for that article. Its reusable hook, simulated stream/history component, and stylesheet live in `assets/examples/chat-scroll/`; the hook is rendered directly into both HTML and Markdown, and all three source files are downloadable. `assets/js/chat-scroll-demo.tsx` mounts and unmounts it through Turbo navigation. Run `npx playwright test tests/accessibility/chat-scroll.spec.mjs` after `npm run build` to check following, pausing, returning to the bottom, history anchoring during streaming, layout changes, keyboard access, cleanup, themes, and the JavaScript-free fallback in Chromium and WebKit.

Articles live in `content/blog/`; case studies live in `content/work/`. Preserve historical dates and slugs. Historical posts have `archived: true` in their frontmatter; omit this field for new writing. Date ranges and article counts are derived from the posts. Original article assets and redirects live in `static/`; case-study images live in `assets/images/`.

Blog tags are native Hugo taxonomies. Tags in article headers, archive rows, and related writing link to `/tags/<term>/`, which lists matching posts by year, newest first. `/tags/` lists all topics and article counts. Both the tag index and individual topics have Markdown exports and appear in the sitemap and `llms.txt`. Tag navigation works without JavaScript; `npm run check` verifies every article tag and each topic's exact membership.

Search opens a native popover from the shared header and mobile menu. Its Stimulus controller lazily loads `/search.json`, searches titles, topics, and page text, and highlights literal matching words in titles, excerpts, and tag links. The index covers the homepage, every article, and the full case studies, including structured content. Search uses the same Markdown content partials as the exports so the case-study text stays complete. Native clear, Escape, outside-click dismissal, a dynamic Tab/Shift+Tab focus trap with an inert background, focus restoration, retry, stale-request protection, and Turbo cleanup are handled without a separate search page. The compact popover is horizontally centered near the top, with a fixed query row and independently scrolling results. It uses a 180ms fade and small transform for pointer opening/closing; reduced motion keeps only a 100ms fade, and keyboard actions stay immediate. Without JavaScript, the popover provides native browse links.

Case-study images are optimized through `layouts/partials/case-study-image.html`. Display images, full-resolution image links, and Markdown image exports use WebP; source PNGs and JPEGs remain in `assets/` without being published as project downloads. The article image hook preserves accessible alternative text and presents archived animations as single-frame WebP posters. Posters are flattened through PNG before WebP encoding, while the playback source is an animated WebP. The original GIF remains available through its explicit download link. The build check verifies both formats and rejects animated posters; Stop, reduced motion, hidden tabs, and navigation restore the still WebP.

Both active font families are preloaded from HTML, so JetBrains Mono does not wait for stylesheet discovery. The shared page template emits Cloudflare's `email_off` comments around the body to keep the public contact links working without its injected email-decoding script. Verify the Cloudflare response after deployment, since local builds do not run its HTML rewriting.

Run `npm run build:social` to render 1200 × 630 share cards with the site’s DM Sans typography, ultramarine palette, solid resting letterforms, and real project screenshots. These existing ultramarine cards and the identity icons intentionally retain their artwork palette after the neutral-header refinement; they do not mirror the current page background. Every article gets a dedicated card using its full title, original publication year, and topics from the content frontmatter; the archive keeps its “Things I’ve learned” card. Re-run this command after changing article titles or adding posts. Hugo converts these exports to JPEG and publishes content-hashed URLs for Open Graph and Twitter metadata. Metadata, structured data, and sharing images are generated by `layouts/partials/seo.html` and `layouts/partials/social-image.html`. RSS includes all blog posts, with the newest writing first, and excludes case studies.

Machine-readable content is generated by Hugo: `/llms.txt`, `/index.md`, `/blog/index.md`, all article Markdown pages, and all three case-study Markdown pages. Case studies include their full prose, captions, full-resolution WebP image links, and attribution. Archived articles retain their original dates and code examples, with an archive notice. `npm run check` verifies every exported Markdown page and its local links.
